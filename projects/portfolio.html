A question-to-evidence-to-answer workflow.

I built this site’s AI assistant to help visitors explore my work in their own words and follow an answer back to its published source.

  1. Resolve the question’s topic, using up to four recent questions for follow-ups.
  2. Retrieve curated portfolio evidence shared by the browser and API.
  3. Send the current question, resolved topic, and evidence to Groq’s Responses API from the server. Generated answers are never reused as evidence.
  4. Stream the answer to the browser with numbered, clickable source references.

This is a conversational AI workflow. It answers questions; it does not autonomously change external systems. Common questions such as hiring and work-history duration use prepared, cited answers without consuming model quota.

The model is one part of the system.

The assistant validates citation numbers against supplied sources and checks Setwise answers for active-development status. Those checks verify reference integrity and a specific status requirement; they do not prove every claim is true.

Provider failures, incomplete or invalid answers, timeouts, and API version mismatches fall back to local portfolio evidence. Visitors can stop a response or clear their recent-question context.

Provider credentials stay on the server. Request validation, bounded history, and per-instance throttles constrain requests.

Automated tests cover API behavior, citation validation, follow-up topic resolution, and browser failure and fallback flows.

How your questions are used.

  • Your question and up to four recent questions are sent to the AI service (Groq) so follow-up questions make sense. Recent questions stay in browser memory and are cleared with Start over.
  • Questions and answers may be logged privately for up to three months to improve the assistant, with best-effort redaction of common contact details and secrets.
  • The provider’s own retention follows its policies. Please leave personal information out of your questions.

Make quality inspectable.

The published assistant evaluation shows synthetic questions, expected source selection, content checks, valid citation references, and mocked failure behavior. It separates deterministic regression results from live-model accuracy, which still needs human review.

A static site with a focused backend.

The frontend is static-first, hosted on GitHub Pages, with a separate Vercel API for AI answers. Engineering case studies, a printable résumé, and evidence search remain available without a model response.

The build validates local links and evidence anchors and publishes an allowlisted static output that excludes backend code and credentials.

Engineering focus: connecting a model to useful evidence, clear interaction design, and explicit failure behavior.
